# Changelog

Every notable change to Shadowlap is listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The release workflow lifts a version's section into its GitHub release notes.

## [Unreleased]

The first release: record, replay and fork AI agent runs, find the call that lost a run, and prove a fix before it ships.

### Added

#### Record

- **`shadowlap demo`** shows the whole loop in about half a minute, with no key and nothing to clone: a refund agent recorded breaking its policy, replayed with 0 upstream requests, blamed to the model call that lost the run, and repaired, its fix proven and applied, against a scripted model on 127.0.0.1 that the demo says is scripted. `--keep <dir>` keeps its folder to open in the dashboard.
- **Model calls at the HTTP layer.** A sidecar on 127.0.0.1 records calls to Anthropic, OpenAI and OpenAI-compatible servers (Ollama, vLLM, OpenRouter, Groq) and Gemini, streaming responses byte for byte with their timing. `shadowlap run` points the official SDKs at it through their base-URL variables, so model calls need no code changes. Credentials are forwarded and never stored, and a model call's query string is kept, and matched, without the credentials in it.
- **Amazon Bedrock, Vertex AI and Azure OpenAI**, whose clients sign requests or fix their endpoint in code, are captured inside Node and Python agents and forwarded unchanged, signatures and HTTP/2 included, as are Claude on Microsoft Foundry and OpenAI's SDK on Bedrock. Any other host that speaks one of their formats, such as a gateway or a company's own proxy, is declared under `providers` in `shadowlap.config.json` and recorded as that format's calls.
- **What the agent saw is what is recorded.** An agent that leaves before its answer is whole ends the request upstream too, and is recorded as a disconnect its retry matches; a stream the provider cuts part way breaks at the same place on replay; identical retries that race each other keep their own answers; and a call's rows wait their turn while another process holds the store. A Realtime WebSocket is tunnelled to its provider's hosts, unrecorded and named in the run's summary, and an SDK's own telemetry passes through and is never recorded.
- **Tools, clock and randomness** through the TypeScript and Python SDKs. A tool declares its effect, `pure`, `read` or `write`; outside Shadowlap the wrapper is a passthrough, so it ships to production unchanged. The Python SDK records coroutines, async generators and async callables under asyncio, trio and anyio, is typed (`py.typed`, mypy `--strict`), and brings a `shadowlap` command that runs the CLI at its own version; the Node SDK loads in an Edge runtime or a browser bundle, and ships a CommonJS copy for `require()`.
- **HTTP hosts as tools.** Hosts declared under `http` in `shadowlap.config.json`, such as a vector database or an internal API, are recorded as tool calls with an effect, from Node and Python.
- **MCP servers** behind `shadowlap mcp`, a proxy that records, replays and fences `tools/call`, with effects from the tools' annotations, for a server it starts or one it reaches over HTTP, and served to the client over stdio or, with `--listen`, over HTTP on a loopback address.
- **Framework adapters**, each tested against the real framework: the Vercel AI SDK, OpenAI Agents SDK, Mastra, LangChain and LangGraph and the Anthropic tool runner in TypeScript; Pydantic AI, the OpenAI Agents SDK, LangGraph, CrewAI, Google ADK, LlamaIndex, Microsoft Agent Framework, Strands, smolagents and Agno in Python; and the Claude Agent SDK in both, its built-in tools (Bash, Write, Edit and the rest) recorded and fenced through its hooks. A Claude Code or Claude Agent SDK recording replays in the next session and on another machine with no normalizer.
- **Scopes** for parts of an agent that run at once, so concurrent sub-agents keep their own recorded answers.
- **`shadowlap init`** finds a project's model SDKs, framework, agent command and tools, suggests an effect for each tool, warns about a client that bypasses the sidecar and about a Node pinned before 18.18, and prints the steps to a first recording.
- **`shadowlap doctor`** checks Node and its SQLite, the guard preloads, Python, the store and the configuration, gives the fix for each problem it finds, and explains the newest run whose agent loaded no preload.
- **The Node it needs, in one line.** The CLI runs on Node 22.16 or later, not 23, whose built-in SQLite has the full-text search every store uses; on another it says so before it loads. An agent on a Node before 18.18, which refuses the guard's preload, is named the same way, and no empty run is kept of it. When a launcher such as `npx node@18.17.0` picks that Node, `run` and `replay` can't ask it: they keep the empty run, and its summary says what Node's refusal above it means.

#### Replay and fork

- **A clean replay makes no upstream requests.** Calls match by what they ask, `(kind, fingerprint, occurrence)`, never by the order they arrive in, so parallel calls replay in any order. A clock, random or pure read the recording never held is answered live and the replay goes on, and a replay of a 1,000-call run starts in well under a second.
- **A clean replay needs no real key.** An agent whose model client takes its key from the environment, as `new Anthropic()`, `new OpenAI()` and Google's clients do, replays without one: `shadowlap test`, the Action, recorded tests, `calibrate` and `bisect` give it a placeholder key for each provider whose credentials the environment lacks, and `shadowlap replay` for each whose key the recording's environment held, never in place of a credential you have, of any kind the provider's SDKs read. The sidecar refuses a live call that would carry one, with one line, so a placeholder never reaches a provider.
- **A fork at the first changed request**, with a structural diff against the closest recorded call and a normalizer hint when the change is a date or an id. After it, model calls and `read` tools run live and `write` tools are blocked or stubbed (`--writes`). A fork of an OpenAI Responses run that continues a stored response sends the conversation in full, rebuilt from the recording, and one that names a stored conversation is refused with the reason.
- **A network guard** reports or refuses the connections and UDP sends that bypass Shadowlap (`--guard`), in Node and in Python, asyncio and uvloop included. Each process says when the guard loaded, so a run it never watched is named, and under `--guard block` fails.
- **Tools Shadowlap never recorded, named.** `run`, `replay` and `show` name each tool the model called, read from its own answers, that the run didn't record, with how often and what it does. `replay` and `test` refuse to run one that writes, a built-in such as Bash or a name such as `send_email`, until it is wrapped, declared a read under `tools.unrecorded`, or allowed with `--allow-unrecorded`.
- **Fewer false forks.** Dates and times near a run's start match across days, and `shadowlap calibrate` replays offline until clean, proposing a normalizer for each value the agent makes anew on every run.
- **What-ifs at call *k*:** `--override` a tool result, `--inject` an instruction, `--set` a request field, switch the `--model`, force a tool live (`--live-tool`) or a call (`--diverge-at`), apply a changed prompt from a later call (`--prompt-from`), and answer a model call with an HTTP failure (`--fail-at`), which sends nothing upstream.
- **`--repeat n`** runs a fork *n* times and shows the paths the attempts took; **`--watch`** replays again on every save.
- **The decision diff.** `shadowlap decisions` asks each recorded model call again with only a change swapped in (a model, a request field, or the system prompt and tools the working tree sends) and ranks what the model decides differently by consequence, a changed write first, with no tool run. Each step is asked several times under the change and as recorded, so a change ranks only when it shows beyond the model's own variation (`--samples`). `shadowlap migrate --to <model>` does it for a model a provider retires, verifies the runs whose writes change, compares the cost per run and says what to set; the providers' retirement dates ship with their sources, and nothing calls home.
- **Partial recordings.** A run imported from a capture holds only model calls; a replay runs everything else live, with writes still fenced.

#### Fixes

- **`shadowlap blame`** finds the model call that lost a failed run: the last one whose answer, asked again, lets the run pass. It probes with forks that replay everything before the probed call, halving the run each time, and reports the call, or the calls it was lost between when no single one is pinned, a confidence read from the error bound of its probes, its 5% risk spread over them, and what the model answered there in the recording and in a fork that passed. `--scope`, `--model`, `--set`, `--budget` and `--json`.
- **`shadowlap verify`** accepts a change only when the failing runs it was written for are fixed, failing runs held out from it are fixed too, and no good run is 10 points or more worse than the same run under the code before the change, paired attempt for attempt, or than its golden's history, each decided at a stated risk. A replay that forks nowhere settles its run in one free attempt. It exits 0 when it accepts, 1 when it rejects and 3 when it can't decide, and reports each run's token and cost change.
- **`shadowlap repair`** blames the failing runs, asks a repairer you choose for rewrites of the system prompt or a tool description, and keeps the smallest rewrite verify accepts, including on failing runs the repairer never saw. A repairer is any Claude model through the Anthropic SDK, any Chat Completions API, or your own Claude Code (`--repairer claude-code`). A rewrite keeps exactly the placeholders of the text it replaces and adds none, each candidate is verified in a temporary git worktree, never in your working tree, a rewrite whose own words grow the input past `--max-growth` is set aside before verify spends anything, and the repairer is given up on after `--repairer-timeout`. The fix comes as a patch, a pull request body and a recording of each fixed run; `--apply`, `--branch` and `--pr` hand it over.
- **Outcome checks** say what a passing run does (`--expect`, or `tests` in the config): tools that must or must not be called and with what arguments, call counts, token and cost budgets, and text in the output or the final answer.
- **Checks on order, conditions and earlier calls' values.** A `calls` rule says what every call of a tool comes after and what its arguments must be, against a value read from an earlier call (`"amount": {"<=": "@lookup_order.result.total"}`); a `when` rule applies checks once a call met a condition. Each check comes out passed, failed, inconclusive or not applicable, and a pass never rests on a value that was not there. `shadowlap check` tries a check on the recordings at no cost, and `doctor` names a misspelt tool or value.
- **Judge checks** ask a model a yes-or-no question about a run. The judge's call is recorded like any model call, so a golden is judged once when it is packed and every clean replay after is judged from the recording, free and the same every time; a fork asks the judge live, and its cost is reported apart from the agent's.
- **Gates with stated error rates.** verify decides each failing run, and blame each probe, by a sequential test between two pass rates as attempts come in, instead of a fixed count, and verify keeps a good run against its baseline by a test whose error holds at every look. Every verdict shows its tally and a bound that holds however its gate stopped (`passed · 12 of 12 · rate >= 0.73 (95%)`), and a good run its baseline's tally and a bound on its drop. An attempt the provider couldn't answer (a 429, a 5xx, a dropped connection) is run again and never counted, so an outage leaves a verdict inconclusive, never failed.

#### Tests and CI

- **`shadowlap test`** replays committed recordings offline and fails on a divergence, a live call, a non-zero exit or a failed check, with JUnit, JSON and Markdown reports and pull request annotations. A recording marked `fork` may diverge and passes on its checks, repeated when a model varies.
- **Exit statuses a script can tell apart:** 0 when all is well, 1 when a check, gate or test failed, 2 for a command it can't run as given, 3 for a verdict that couldn't be reached, 70 for a bug in Shadowlap, and 128 + n for a stop signal: 130 for Ctrl-C, and 129 for a closed terminal, which stops the demo, `replay --watch`, `serve`, `tasks serve`, `mcp` and `repair` as it stops a run.
- **A GitHub Action**, `devjoinedthechat/shadowlap`, that replays the recordings, puts the diff of each failure in the job summary and on the pull request, and keeps one comment on a pull request with each golden's verdict, edited in place and compared with the base branch's last session when the test history has one. It installs its own release of the CLI from npm, and a build from source gets none of the job's secrets.
- **Fix on failure.** With `fix-on-failure`, the Action blames a golden that fails a check, has a fix proposed and verified on the other goldens that fail the same check, those held out from the repairer among them, and on goldens that pass it, and opens a pull request whose checks start: with a `github-token`, or with the job's own token and a `workflow_dispatch` of the workflow on the fix's branch. The pull request says what the fix was verified on, and never claims checks it didn't see. The dashboard's Settings → CI writes the step with the permissions it needs.
- **Recorded tests** for your own suite: a pytest plugin (`@pytest.mark.shadowlap`) and `@shadowlap/test` for Vitest, Jest and node:test. A test records on its first run and replays offline after that.
- **Gated goldens.** A golden that may fork can be decided by a sequential test between two pass rates, or against its own test history, stopping as soon as the evidence is enough. A history baseline takes only sessions that passed on the default branch, so a regression never becomes the standard it is judged by. `--inconclusive fail|warn` says what CI does when a gate, a check or an injection test can't decide, and the Action can keep the test history between jobs.
- **One risk for the whole suite.** `shadowlap test` keeps the chance that a healthy suite goes red for nothing within `--suite-risk`, 5% by default, by splitting it across the gated goldens, sizes each gate's limit to fit, and says before it runs what the session will cost in attempts and dollars.
- **Injection tests.** `shadowlap injection` plants payloads in every read of a tool marked untrusted, each carrying a canary that occurs nowhere else, so a tool call carrying it proves the planted text caused it; `--clean` asks whether a recorded read caused a write. A golden's `injection` gate fails CI while the agent obeys.
- **Error-path presets.** `shadowlap test --chaos` forks each golden where a tool times out or answers nothing, malformed or oversized JSON, or the provider answers 429 or 500, and judges each fork by the checks that hold on any path.
- **Production coverage.** `shadowlap coverage` groups imported production runs by behaviour, names those no golden covers, and `--pack` makes a golden of one run of each.

#### Imports, exports and data

- **`shadowlap import har`, `nock`, `vcr` and `litellm`** turn a capture into a recording you replay your own code against; a LiteLLM gateway's production traffic becomes one run per correlation id.
- **Traces you already keep** become recordings: `shadowlap import otel` reads OTLP JSON with the OpenTelemetry GenAI or OpenInference conventions, and `langfuse`, `langsmith`, `phoenix` and `logfire` fetch a trace from Langfuse, LangSmith, Arize Phoenix or Pydantic Logfire with the keys in the environment, never storing them. Without a trace id, `langfuse`, `phoenix` and `logfire` bring every trace that started in a window (`--since 7d`, `--until`, `--limit`, `--trace-name`), one run per trace, and skip the traces imported before; Langfuse is read through its Observations API where the server has it. What the trace kept replays; the rest runs live, with writes fenced. The dashboard's Import dialog fetches from all four.
- **Exports:** `pack` (redaction rules applied), `export html` (a run as one file with the dashboard's views), `export har`, `export otel` (GenAI semantic conventions) and `export dataset` (JSONL, OpenAI chat, Braintrust, Langfuse).
- **Recordings as data:** labels and notes that travel in packs, full-text search across prompts, responses and tool calls, and `shadowlap diff`, which starts with what changed between two runs. A label or note made while a run ends is kept with what the run wrote, and a store or a collector that can't write for a full disk says the disk is full.
- **`shadowlap rm` and `gc`** delete runs, old ones by age or count, and remove the recorded data nothing references any more.
- **JSON for scripts and coding agents** from `ls`, `show`, `search`, `diff`, `calibrate`, `label`, `blame`, `verify`, `repair` and `test`, and instructions to give Claude Code, Codex, Cursor and other coding agents.
- **The coding agents' instructions, packaged as skills.** `setup-agent` sets Shadowlap up for an agent (its tools' effects from their code, a first recording, a clean replay, goldens, the CI check), and `debug-agent` checks every change to the agent's prompt, tools, model or code against what it actually did, and debugs a failing run through to a verified fix. `shadowlap skill install` puts them into a project from the copy that ships with the CLI: as a Claude Code plugin in `.claude/skills/shadowlap/`; with `agents` (or `codex`, `cursor`, `copilot`, `gemini` and the other names) into `.agents/skills/`, where Codex, Cursor, GitHub Copilot, Gemini CLI, Windsurf, OpenCode, Cline, Amp, goose, Zed and Junie read skills; with `kiro` into `.kiro/skills/`. The repository is also its own Claude Code plugin marketplace, and CI runs every command the skills name against the reference agent and checks every installed copy with the Agent Skills reference validator.
- **The recording format, specified.** docs/recording-format.md, version 1: packs on disk and the recordings protocol over HTTP, with Shadowlap as the reference implementation.
- **A service the agent calls, recorded as a tool.** docs/downstream-services.md shows how a declared host's answers replay without the service.

#### Team store

- **Your team's runs in a bucket you own**, free and open source like the rest, with nothing to buy or add first. `shadowlap store set` names an Amazon S3, Cloudflare R2 or other S3-compatible bucket, a Cloud Storage bucket or an Azure Blob container in `shadowlap.config.json`, and every machine reaches it with its own credentials, found where the cloud's own tools keep them. Nothing is hosted, there are no accounts, and no cloud SDK is bundled.
- **`shadowlap push` and `pull`** send runs with their lineage, each blob once, and a run still recording when it ends, and bring teammates' runs back, checked as strictly as a pack. Labels and notes merge both ways, and every run says who made it, and in CI which CI. A pulled run reads as its author's recording, with the requests it sent and what it spent there (*≈$0.0030 spent · by maya*), and its replay asks before running the command it was recorded with.
- **`shadowlap test --push`** sends every test run and the session's report from CI; `shadowlap store ci` prints the step, with short-lived credentials wherever the CI and the cloud allow them and the provider keys its goldens that run live need, and `store push-from-ci off` turns it off for the whole team.
- **Pull requests stay in their own folder.** A pull request's CI job writes only under `pr/<number>/`, a pull leaves those folders out unless given `--include-pr`, and runs from one never go back into the team's. `shadowlap store policy` prints the two policies that make the cloud hold to it.
- **`shadowlap share`** writes a run's HTML report, with every redaction rule applied, to the bucket and prints a link that expires after 7 days.
- **`shadowlap store check`** proves this machine can list, write, read and delete in the store, and warns when versioning or an object lock is off; `store show` says what this machine knows, without a request.

#### Dashboard and terminal UI

- **`shadowlap dashboard`**: runs and their forks, a strip of every call by origin, the calls, turns, context and cache use, timeline and family of a run, the conversation exactly as the model saw it at any call, streamed responses at their recorded pacing, fork diffs and Compare. Replay and every fork run from the page, and a run downloads as one redacted HTML file. `--port 0` takes any free port, and the link names it.
- **A run opens where it failed**, at its first failing call, its calls grouped under the model call each belongs to and folded at will. Its page names the tools the model called that weren't recorded, a preload that never loaded, the WebSockets it opened and the reads it answered live; Provenance shows the gateway a call went through and the guard, and Tests explains a guard failure.
- **What a fork did differently**: the tool calls it made and didn't, its writes and what became of each, and how each run ended, ranked as `shadowlap decisions` ranks a change.
- **Edit and fork.** Edit a tool's result, or what a person answered, in the call inspector and fork from it.
- **A good/bad key.** `+` and `-` label a run good or bad, which `repair --keeps label:good` keeps working, and the same key again takes it off. Runs keeps its filters in the address, so a view can be shared and Back and Forward work.
- **Fixes shows the evidence.** A gate's attempts are grouped by what each did, and each verdict shows its bound, each good run its baseline and margin, and a blame the calls it was lost between.
- **Large stores and long runs open at once.** The heavy views are worked out on threads beside the server, so every other request is answered meanwhile; a long run's calls come a page at a time, each page's code loads when it opens, and Runs reads only its first page again as runs change.
- **Accessible.** The dashboard's text meets WCAG AA contrast, with a skip link and a focus order that follows the page, and CI checks it in Chromium with axe-core.
- **`shadowlap ui`**: the run tree with check results and labels, a timeline with scopes, the inspector, playback, diffs, and an actions palette with every intervention.
- **Cost, model and stop reason** for every call, from a price table the config can extend.

#### Security

- **Local only.** The sidecar and the dashboard listen on 127.0.0.1 behind a session token; the dashboard checks Host and Origin, runs under a strict Content Security Policy, builds every command itself, and opens your browser without putting the token in any process's arguments.
- **No copy carries a credential.** A model call's query string is kept without its credentials, a captured host's query and form credentials and a response header that hands one back are stored as `<CREDENTIAL>`, and every copy (a pack, an HTML report, a share link, a HAR, a push) leaves out those a recording made by an earlier version kept.
- **Packs and captures are untrusted input:** validated before anything is written, hash-checked, refused on symbolic links and oversized files, each file read on the descriptor it was checked on, credentials dropped. A pack's redaction rules are checked before they run, and replaying a pack's command asks first.
- **Patterns that could stall a replay are refused** wherever a rule is written or read: a backreference, a repeat the next character doesn't settle, more than 10,000 characters.
- **Signed reasoning stays as recorded in a pack**, so a fork's provider accepts it, and `pack` names each redaction rule that matches inside it; a copy that is only read masks it.
- **The team store's folder is all a pull reaches.** It reads only objects named as a push names them, never a key with a `.` or `..` part.
- **Recorded text is escaped** wherever a terminal shows it, stores are readable only by their owner, and a store written by a newer Shadowlap is refused.
- **Telemetry is off:** nothing is sent unless `SHADOWLAP_TELEMETRY_URL` names a collector you run. The collector is in the repository, and refuses any time before 2025 or more than a day ahead of its own clock.

#### Built on

- **Open protocols:** the SDK wire protocol and the recording format are specified, with a conformance suite of fourteen scenarios that needs no API keys. The engine is documented as a library.
- **Few runtime dependencies, held by a test.** The engine, sidecar, SDKs and adapters install nothing else. The CLI adds commander, and the terminal UI, which the CLI and the dashboard use, adds Ink and React.
