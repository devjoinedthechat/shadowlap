# Changelog

Every notable change to Shadowlap is listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The release workflow lifts a version's section into its GitHub release notes, and publishes nothing for a version without one.

## [Unreleased]

The first release: record, replay and fork AI agent runs, find the call that lost a run, and prove a fix before it ships. Each entry links to the page with its details.

### Added

#### Get started

- **[`shadowlap demo`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#demo)** shows the whole loop in about half a minute, with no key and nothing to clone. It records a refund agent, replays it with 0 upstream requests, and blames and repairs it against a scripted model on 127.0.0.1; `--keep <dir>` keeps its folder to open in the dashboard.
- **[`shadowlap init`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#init)** finds a project's model SDKs, framework, models, agent command and tools, and prints the steps to a first recording. It suggests an effect for each tool, and warns about a client that bypasses the sidecar or a Node pinned before 18.18.
- **[`shadowlap doctor`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#doctor)** checks Node and its SQLite, the guard preloads, Python, the store and the configuration, and gives the fix for each problem. It also explains the newest run whose agent loaded no preload.
- **[The Node it needs, in one line](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md)**. The CLI runs on Node 22.16 or later, not 23, and on another Node says so before it loads. An agent on a Node before 18.18, which refuses the guard's preload, is named the same way.

#### Record

- **[Model calls at the HTTP layer](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md)**. A sidecar on 127.0.0.1 records calls to Anthropic, OpenAI, OpenAI-compatible servers (Ollama, vLLM, OpenRouter, Groq) and Gemini, keeps streamed responses byte for byte with their timing, and needs no code changes. Credentials are forwarded and never stored.
- **[Cloud clients and gateways](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/providers.md#in-process-capture)**. Amazon Bedrock, Gemini Enterprise Agent Platform (Vertex AI), Azure OpenAI, Claude on Microsoft Foundry and OpenAI's SDK on Bedrock are captured inside Node and Python agents, and forwarded unchanged, signatures included. Calls to Vercel's AI Gateway, and to any host declared under `providers` in `shadowlap.config.json`, are recorded too.
- **[What the agent saw is what is recorded](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md#the-replay-state-machine)**. Disconnects, cut streams, unreachable providers and the sidecar's own answers replay as they happened. A request's numbers are kept as sent: an id past 2^53 keeps its digits through a replay, an override, a pack and Compare.
- **[Recording waits out a busy store](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md)**. No run is left marked as running, and a run whose start can't be written whole, as on a full disk, leaves nothing behind. `run`, `replay` and `test` say in their summary what couldn't be written.
- **[HTTP hosts as tools](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/sdk.md#http-services-without-wrapping)**. Hosts declared under `http` in `shadowlap.config.json`, such as a vector database or an internal API, are recorded as tool calls with an effect, from Node and Python. So [a service the agent calls](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/downstream-services.md) replays without the service.
- **[MCP servers](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/mcp.md)** behind `shadowlap mcp`, a proxy that records, replays and fences `tools/call`, with effects from the tools' annotations. It starts a server or reaches one over HTTP, and serves the client over stdio or, with `--listen`, over HTTP on a loopback address.
- **[An MCP server's HTTP errors replay as the client got them](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/mcp.md#other-behaviour)**. Through `--listen`, a tool call answered with a 503 or another answer that is no MCP message replays with the same status, headers and body, and so does the 502 the proxy gives when the server can't be reached.
- **[One folder for this machine's files](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#environment)**. `SHADOWLAP_HOME` moves every file Shadowlap keeps outside a project, `~/.shadowlap` by default: the dashboard's project list, and the agents and `mcp --listen` proxies registered while they run. Commands and proxies given the same one find each other there.

#### SDKs and frameworks

- **[Tools, clock and randomness](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/sdk.md)** through the TypeScript and Python SDKs. A tool declares its effect, `pure`, `read` or `write`, and outside Shadowlap the wrapper is a passthrough, so it ships to production unchanged.
- **[Streams and errors replay as recorded](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/sdk.md)**. A streaming tool replays every value it yielded and whether its caller stopped early. A replayed error is the one recorded, in Python an instance of the same builtin.
- **[The Python SDK](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/sdk.md)** records async tools under asyncio, trio and anyio, where a call cancelled while it waits on the sidecar never runs and never stays pending. Its guard and capture are tested on Python 3.9 to 3.14.
- **[The Node SDK](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/sdk.md)** loads in an Edge runtime or a browser bundle, and ships a CommonJS copy for `require()`.
- **[Scopes](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/sdk.md#scopes)** for parts of an agent that run at once, so concurrent sub-agents keep their own recorded answers.
- **[Framework adapters](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/frameworks.md)**, each tested against the real framework running its own agent loop:
  - TypeScript: the Vercel AI SDK, OpenAI Agents SDK, Mastra, LangChain, LangGraph and the Anthropic tool runner.
  - Python: Pydantic AI, the OpenAI Agents SDK, LangChain, LangGraph, CrewAI, Google ADK, LlamaIndex, Microsoft Agent Framework, Strands, smolagents and Agno.
- **[The Claude Agent SDK](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/frameworks.md#claude-agent-sdk)**, in TypeScript and Python: its built-in tools (Bash, Write, Edit and the rest) are recorded and fenced through its hooks, and the fence holds against other hooks. A Claude Code or Claude Agent SDK recording replays in the next session and on another machine with no normalizer.

#### Replay and fork

- **[A clean replay makes no upstream requests](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md)**. Calls match by what they ask, `(kind, fingerprint, occurrence)`, never by the order they arrive in, so parallel calls replay in any order. A replay of a 1,000-call run starts in well under a second.
- **[A clean replay needs no real key](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md#keys)**. Offline replays give the agent a placeholder key where the environment lacks one, never in place of a credential you have. The sidecar refuses a live call that would carry one, so a placeholder never reaches a provider.
- **[A fork at the first changed request](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md#where-forks-happen)**, with a structural diff against the closest recorded call, and a normalizer hint when the change is a date or an id. After it, model calls and `read` tools run live, and `write` tools are blocked or stubbed (`--writes`).
- **[State the recording left with the provider is rebuilt for a fork](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md#where-forks-happen)**: a stored response's conversation, a Gemini or Vertex AI context cache, and an uploaded file, within the provider's limits. What can't be rebuilt is refused or named, with the reason.
- **[A network guard](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md#the-network-guard)** reports or refuses the connections and UDP sends that bypass Shadowlap (`--guard`), in Node and in Python. A run it never watched is named, and under `--guard block` fails, never called clean.
- **[A `--listen` proxy under the network guard](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/mcp.md#under-the-network-guard)**. An agent reaches one under `block` with no warning, even one started after it, by its own command say. A proxy proves it runs with a key it holds, so a registration a killed proxy left lets nothing through, even once its process id is reused.
- **[The Claude Code CLI under the guard](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/frameworks.md#claude-agent-sdk)**. It loads no preload, so the fence names what it can still reach, and `withFence` turns off its nonessential traffic. `guard.accept: ["claude-code"]` (or `SHADOWLAP_GUARD_ACCEPT`) accepts that CLI alone, keeping block for Node and Python.
- **[Tools Shadowlap never recorded, named](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md#tools-shadowlap-did-not-record)**. `run`, `replay` and `show` name each tool the model called that the run didn't record. Every command that replays a run refuses one that writes, or one of unknown effect, until it is wrapped, declared under `tools.unrecorded`, or allowed with `--allow-unrecorded`.
- **[Fewer false forks](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/normalizers-and-redaction.md#calibrate)**. Dates and times near a run's start match across days, and `shadowlap calibrate` replays offline until clean, proposing a normalizer for each value the agent makes anew on every run.
- **[What-ifs at call *k*](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/interventions.md)**: `--override` a tool result, `--inject` an instruction, `--set` a request field, switch the `--model`, force a tool live (`--live-tool`) or a call (`--diverge-at`), and apply a changed prompt from a later call (`--prompt-from`). `--fail-at` answers a model call with an HTTP failure, which sends nothing upstream.
- **[`--repeat n`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#repeating-a-fork)** runs a fork *n* times and shows the paths the attempts took; **`--watch`** replays again on every save.
- **[Partial recordings](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/how-it-works.md#partial-recordings)**. A run imported from a capture holds only model calls; a replay runs everything else live, with writes still fenced.

#### Find and fix

- **[`shadowlap blame`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/blame.md)** finds the model call that lost a failed run: the last one whose answer, asked again, lets the run pass. It probes with forks that replay everything before the probed call. It reports the call with a confidence, the calls it was lost between or gradually around, or *Inconclusive at the first model call*.
- **[`shadowlap verify`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/verify.md)** accepts a change only when the failing runs it was written for, and those held out from it, are fixed, and no good run is 10 points or more worse than before. It exits 0 when it accepts, 1 when it rejects and 3 when it can't decide. Its report says what answered tool calls after each fork.
- **[`shadowlap repair`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/repair.md)** blames the failing runs, asks a repairer you choose for rewrites of the system prompt or a tool description, and keeps the smallest rewrite verify accepts twice, the second time with fresh attempts. However many candidates it tries, the chance it keeps one that falls short stays within the gate's risk.
- **[Repairers](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/repair.md#the-repairer)**. A repairer is any Claude model through the Anthropic SDK, any Chat Completions API, or your own Claude Code (`--repairer claude-code`, 2.1.248 or later). Every answer is held to the 16,000 tokens the budget counts.
- **[Claude Code as the repairer runs restricted](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/repair.md#the-repairer)**: no tools, no MCP server, no session kept on disk, and none of your user, project or local settings.
- **[Each candidate in a worktree of its own](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/repair.md)**. A candidate is verified in a temporary git worktree, with `--build` run in it on a `node_modules` of its own. Repair reads nothing in git's own folder or in a file git ignores, so a token in the git config or a `.env` never reaches the repairer or a report.
- **[The fix, handed over](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/repair.md)**: a patch, a pull request body and a recording of each fixed run. `--apply`, `--branch` and `--pr` hand it over.
- **[Fixes, kept](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#fix)**. A blame opens a fix, or joins one, by the run's labels, else its check, and verify and repair report to it. `shadowlap fix ls` and `fix show` say how far each step got.
- **[A verify from a fix holds out what its repair held out](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/tui.md#repair-and-verify)**. The terminal UI's `V`, the dashboard's Verify step and `fix apply`'s next step pass the runs a repair kept from its repairer as `--holdout`, so a change is tried on failing runs it was not written for.
- **[Output that fits the terminal](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#blame)**. The prose blame, repair and verify print, before they start, as they go and in their reports, and what the demo says, wraps at whole words to the terminal's width, each line indented as the first. Commands, paths and tallies keep their lines. Written to a pipe or a file, each line stays whole.
- **[`fix apply`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#fix)** puts a verified fix's patch into the working tree, and copies the fixed runs in as goldens and tests them. Each takes the fix's label as its name, unless `--name <run>=<name>` or the dashboard's Apply fix names it. It replays the other goldens offline to name each the patch makes diverge, none from a pack the repository doesn't track.

#### Model and prompt changes

- **[The decision diff](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/decisions.md)**. `shadowlap decisions` asks each recorded model call again with only a change swapped in (a model, a request field, or the system prompt and tools the working tree sends), and ranks what the model decides differently, a changed write first. No tool runs, and a step ranks only beyond the model's own variation (`--samples`).
- **[`shadowlap migrate --to <model>`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/decisions.md#migrate)** does it for a model a provider retires: it runs end to end every run a preview can't clear, compares the cost per run and says what to set. The providers' retirement dates ship with their sources, and nothing calls home.

#### Checks and gates

- **[Outcome checks](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/checks.md)** say what a passing run does, with `--expect` or under `tests` in the config. They cover the tools that must or must not be called and with what arguments, call counts, token and cost budgets, and text in the output or the final answer.
- **[Checks on order, conditions and earlier calls' values](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/checks.md)**. A `calls` rule says what every call of a tool comes after, and what its arguments must be, against an earlier call's value (`"amount": {"<=": "@lookup_order.result.total"}`). A `when` rule applies checks once a call met a condition.
- **[`shadowlap check`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#check)** tries a check on the recordings at no cost.
- **[Judge checks](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/judges.md)** ask a model a yes-or-no question about a run. The judge's call is recorded like any model call, so a golden is judged once when it is packed, and every clean replay after is judged from the recording, free and the same every time.
- **[Gates with stated error rates](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/gating.md#verify-and-blame)**. `verify` decides each failing run, and `blame` each probe, by a sequential test between two pass rates as attempts come in, and every verdict shows its tally and a bound (`passed · 12 of 12 · rate >= 0.73 (95%)`).
- **[Every risk a verdict line prints holds exactly at every look](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/gating.md)**. Labels round a confidence down and a risk up.
- **[An outage never fails a verdict](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/gating.md#when-the-provider-is-unavailable)**. An attempt the provider failed before the model answered is run again and never counted; one it cut short after counts against either verdict, so an outage leaves a verdict inconclusive.
- **[A flaky provider stops a long run no more often than a short one](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/gating.md#when-the-provider-is-unavailable)**: a long run takes one more error in a row to stop for each tenfold of its attempts.
- **[Gated goldens](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/gating.md#a-gate-against-history)**. A golden that may fork can be decided by a sequential test between two fixed pass rates, or against its own test history, stopping as soon as the evidence is enough. A history baseline takes only sessions that passed on the default branch, so a regression never becomes the standard it is judged by.
- **[What CI does with a verdict it can't reach](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/gating.md)**. `--inconclusive fail|warn` says what CI does when a gate, a check or an injection test can't decide. With no `--inconclusive`, a history gate whose golden has fewer than 30 sessions only warns, unless its last sessions fall below the ones before them; a clear failure fails either way.
- **[One risk for the whole suite](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/gating.md#one-risk-for-the-whole-suite)**. `shadowlap test` splits one risk of a healthy suite going red for nothing, `--suite-risk` (5% by default), across the gated goldens. Before it runs, it says what the session will cost in attempts and dollars, and which goldens can't keep within their share and by how much.
- **[Attempts run in turns](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/gating.md)**, so a burst of failures lands on many goldens once each, and a session stops at 3 + ⌈log₁₀ goldens⌉ errors in a row.

#### Tests and CI

- **[`shadowlap test`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/ci.md)** replays committed recordings offline, and fails on a divergence, a live call, a non-zero exit or a failed check, with JUnit, JSON and Markdown reports and pull request annotations. A recording marked `fork` may diverge and passes on its checks, repeated when a model varies.
- **[Exit statuses a script can tell apart](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md)**. A command exits 0 when all is well, 1 when a check, gate or test failed, 2 when it can't run as given, and 3 when it reached no verdict. A bug in Shadowlap exits 70 (`mcp` included), and a stop signal 128 + n: 130 for Ctrl-C and 129 for a closed terminal.
- **[A GitHub Action](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/ci.md#github-actions)**, `devjoinedthechat/shadowlap`, replays the recordings, puts the diff of each failure in the job summary and on the pull request, and keeps one comment on a pull request with each golden's verdict. It installs its own release of the CLI from npm without running an install script.
- **[Fix on failure](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/ci.md#fix-on-failure)**. With `fix-on-failure`, the Action blames a golden that fails a check, has a fix proposed and verified on the other goldens that fail it, some held out from the repairer, and on goldens that pass it, then opens a pull request. A pull request from a fork gets no fix.
- **[Recorded tests](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/testing.md)** for your own suite: a pytest plugin (`@pytest.mark.shadowlap`) and `@shadowlap/test` for Vitest, Jest and node:test. A test records on its first run and replays offline after that.
- **[Injection tests](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/injection.md)**. `shadowlap injection` plants payloads in every read of a tool marked untrusted, each carrying a canary that occurs nowhere else, so a tool call carrying it proves the planted text caused it. `--clean` asks whether a recorded read caused a write, and a golden's `injection` gate fails CI while the agent obeys.
- **[Error-path presets](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/error-paths.md)**. `shadowlap test --chaos` forks each golden where a tool times out or answers nothing, malformed or oversized JSON, or the provider answers 429 or 500, and judges each fork by the checks that hold on any path.
- **[Production coverage](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/coverage.md)**. `shadowlap coverage` groups imported production runs by behaviour, names those no golden covers, and `--pack` makes a golden of one run of each.

#### Imports, exports and data

- **[`shadowlap import har`, `nock`, `vcr` and `litellm`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#import)** turn a capture into a recording you replay your own code against; a LiteLLM gateway's production traffic becomes one run per correlation id. Every import is judged by the config's rules on calls as it lands, its verdict said, kept on the run and judged again once the rules change.
- **[Traces you already keep](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#traces)** become recordings: `shadowlap import otel` reads OTLP JSON, and `langfuse`, `langsmith`, `phoenix` and `logfire` fetch a trace with the keys in the environment, never storing them. Without a trace id, `langfuse`, `phoenix` and `logfire` bring every trace of a window (`--since 7d`), one run per trace. A Langfuse trace's run links back to it with **Open in Langfuse ↗**.
- **[Exports](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#export-html)**: `pack` (redaction rules applied), `export html` (a run as one file with the dashboard's views), `export har`, `export otel` (GenAI semantic conventions) and `export dataset` (JSONL, OpenAI chat, Braintrust, Langfuse).
- **[Recordings as data](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#label-note)**: labels and notes that travel in packs, full-text search across prompts, responses and tool calls, and `shadowlap diff`, which starts with what changed between two runs. A label or note made while a run ends is kept, and a store or a collector that can't write for a full disk says the disk is full.
- **[`shadowlap rm` and `gc`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/cli.md#rm-gc)** delete runs, old ones by age or count, and remove the recorded data nothing references any more.

#### Coding agents

- **[JSON for scripts and coding agents](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/agents.md)** from `ls`, `show`, `search`, `diff`, `calibrate`, `label`, `blame`, `verify`, `repair` and `test`, and instructions to give Claude Code, Codex, Cursor and other coding agents.
- **[Skills](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/agents.md#the-skills)**. `setup-agent` sets Shadowlap up for an agent, and `debug-agent` checks every change against what the agent did and debugs a failing run to a verified fix. `shadowlap skill install` adds them as a Claude Code plugin, or to `.agents/skills/` or `.kiro/skills/`, where other agents read them.

#### Team store

- **[Your team's runs in a bucket you own](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/team.md)**, free and open source like the rest, with nothing hosted and no accounts. `shadowlap store set` names an Amazon S3, Cloudflare R2 or other S3-compatible bucket, a Cloud Storage bucket or an Azure Blob container, which every machine reaches with its own credentials.
- **[`shadowlap push` and `pull`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/team.md)** send runs with their lineage, each blob once, and bring teammates' runs back, checked as strictly as a pack. Labels and notes merge both ways, and every run says who made it (*≈$0.0030 spent · by maya*).
- **[`shadowlap test --push`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/team.md#push-from-ci)** sends every test run and the session's report from CI. `shadowlap store ci` prints the step, with short-lived credentials where the CI and the cloud allow them and a checkout that keeps no token; `store push-from-ci off` turns it off for the whole team.
- **[Pull requests stay in their own folder](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/team.md#pull-requests)**. A pull request's CI job writes only under `pr/<number>/`, and a pull leaves those folders out unless given `--include-pr`. `shadowlap store policy` prints the two policies that make the cloud hold to it.
- **[`shadowlap share`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/team.md#share-links)** writes a run's HTML report, with every redaction rule applied, to the bucket and prints a link that expires after 7 days.
- **[`shadowlap store check`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/team.md)** proves this machine can list, write, read and delete in the store, and warns when versioning or an object lock is off; `store show` says what this machine knows, without a request.
- **[A pushed fix carries no key, and a pulled one runs nothing it carries](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/team.md)**. Command lines go with their keys masked. A pulled blame or verdict runs without the teammate's `--build`, `--base` and command after `--`, spends at most twice what Shadowlap runs by itself, and runs only after a yes to the exact command line.

#### Dashboard and terminal UI

- **[`shadowlap dashboard`](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/dashboard.md)**: runs and their forks, a strip of every call by origin, the conversation exactly as the model saw it at any call, streamed responses at their recorded pacing, fork diffs and Compare. Replay and every what-if but `--set` run from the page, and a run downloads as one redacted HTML file.
- **[The Overview leads with what needs doing](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/dashboard.md#overview)**: four facts on the week's outcomes, then Needs a look, one row per cause. Each row's step runs or asks from the row, from Run blame to Migrate. Beside it are the newest runs and the activity feed, red where something failed and amber where a check couldn't decide.
- **[A run opens where it went wrong](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/dashboard.md#where-a-run-opens)**: a recording's newest call, a call picked earlier, blame's lost call, where a fork forked, or the call its outcome names. Otherwise, its first failure, write or last model call. Its calls group under the model call each belongs to, and it names the tools the model called that weren't recorded.
- **[What a fork did differently](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/dashboard.md)**: the tool calls it made and didn't, its writes and what became of each (*send_email ×9 blocked, from #950*), and how each run ended, ranked as `shadowlap decisions` ranks a change.

#### Security

- **[Local only](https://github.com/devjoinedthechat/shadowlap/blob/main/SECURITY.md)**. The sidecar and the dashboard listen on 127.0.0.1 behind a session token and check the host every request names, which blocks DNS rebinding. The dashboard checks Origin too, runs under a strict Content Security Policy, builds every command itself, and opens your browser without putting the token in any process's arguments.
- **[No copy of a run carries a credential](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/normalizers-and-redaction.md#redaction)**. A model call's query string and answer headers are stored without their credentials, a captured call's are stored as `<CREDENTIAL>` wherever it sends or gets them back, and its request headers are never stored. Every copy of a run also masks a key its command line carries.
- **[Credentials are masked by a body's shape, not its content type](https://github.com/devjoinedthechat/shadowlap/blob/main/SECURITY.md)**. JSON, lines of JSON, event streams, XML, HTML, forms, multipart parts, GraphQL and `key: value` lines are read, and masked inside their strings too. A body masking can't read is stored as `<CREDENTIAL>` whole.
- **[A command line's secrets wherever a tool takes them](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/normalizers-and-redaction.md#command-lines)**. Every copy masks a secret a tool takes by a word's place (`aws configure set aws_secret_access_key …`, `npm config set`, `mc alias set`, `vault login`, `vault kv put`), `az login`'s and `twine`'s `-p`, `kubectl create secret`'s literals, a libpq connection string's password, any program's `--user user:…`, and a script's `api_key = "…"`.
- **[Secrets a call writes to a store](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/normalizers-and-redaction.md#secret-stores)** are stored as `<CREDENTIAL>`: a Vault KV write's, a Key Vault secret's, Secret Manager's `:addVersion` and a Kubernetes Secret's patch. So is what Vault hands back at another KV mount and from `sys/wrapping/unwrap`. A recording made before still replays, a rotated secret too.
- **[An ARN only as AWS writes one](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/normalizers-and-redaction.md#names-that-hold-a-credential)**. A key under a secret's name that only begins `arn:` is masked, and so is SigV2's `AWSAccessKeyId`. An AWS access key id anywhere else is kept, as a user is beside a masked password.
- **[Credentials stay on their origin](https://github.com/devjoinedthechat/shadowlap/blob/main/SECURITY.md)**. A redirect a captured `fetch` follows to another origin goes without the agent's `authorization`, `cookie` and `proxy-authorization`, and a loop of redirects ends at the twentieth. A model API's redirect is never passed on or replayed.
- **[Packs and captures are untrusted input](https://github.com/devjoinedthechat/shadowlap/blob/main/SECURITY.md)**: validated before anything is written, hash-checked, refused on symbolic links and oversized files, credentials dropped, and a pack's redaction rules checked before they run.
- **[Someone else's command runs only after a yes to it](https://github.com/devjoinedthechat/shadowlap/blob/main/SECURITY.md)**. A golden recorded elsewhere that the repository doesn't track, or a replay of an imported or pulled run, asks at a terminal, runs with `--yes`, and isn't run without one. The question shows the exact command line, and a yes in the dashboard or terminal UI covers only the lines shown.
- **[A capture's message is only ever an argument of your agent's](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/coverage.md)**. `coverage --pack` refuses a command where `{message}` would run as code or name what runs, checks a `{message:/regex/}` as a rule's pattern, and leaves out a capture whose message would start an argument with a dash.
- **[No pattern stalls a replay](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/normalizers-and-redaction.md#patterns-that-could-take-too-long)**. A pattern that could take too long is refused wherever a rule is written or read. The rules a document meets run within 5 seconds, and a replay answers that call with why and goes on.
- **[A repair rewrites only prompt text, and only in a copy](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/repair.md)**. A rewrite keeps exactly the placeholders of the text it replaces and adds no quote or backslash, and is tried in a temporary git worktree with at most 256 MB of untracked files copied in. No candidate touches a recording or Shadowlap's config.
- **[A pulled fix does no more than a repair made here](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/team.md#a-teammates-patch-is-held-to-a-repairs-rewrites)**. A repair rewrites text only in a string of code or config, or in a prose file, and never in what runs. `fix apply` holds a teammate's patch to that in your working tree, and a pull leaves out one to a dot-folder's config, a Dockerfile or a script.
- **[The Action keeps the job's tokens from the agent](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/ci.md#github-actions)**. No GitHub token the job holds reaches the CLI or the agent, a fix's branch is pushed only to the repository the runner names, and the workflows Shadowlap writes check out with `persist-credentials: false` and name no `GH_TOKEN`.
- **[The Action's events and output](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/ci.md#github-actions)**. It runs on `pull_request`, `push`, `schedule`, `workflow_dispatch` and `merge_group` alone, refusing every other event. What a run, a model, the test history or GitHub wrote shows as text in its pull requests, comments and job summaries, and never starts a workflow command in the log.
- **[Signed reasoning stays as recorded in a pack](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/normalizers-and-redaction.md#signed-reasoning)**, so a fork's provider accepts it, and `pack` names each redaction rule that matches inside it; a copy that is only read masks it.
- **[The team store's folder is all a pull reaches](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/team.md)**. A pull reads only objects named as a push names them, never a key with a `.` or `..` part.
- **[Recorded text is escaped](https://github.com/devjoinedthechat/shadowlap/blob/main/SECURITY.md)** wherever a terminal shows it.
- **[A store is its owner's alone](https://github.com/devjoinedthechat/shadowlap/blob/main/SECURITY.md)**. It is readable only by its owner, and opened only as a regular file of theirs, never through a symbolic link, in a directory only they can write to. A store a newer Shadowlap wrote is refused.
- **[Telemetry is off](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/telemetry.md)**: nothing is sent unless `SHADOWLAP_TELEMETRY_URL` names a collector you run. The collector is in the repository, installs nothing but Shadowlap's engine, and refuses any time before 2025 or more than a day ahead of its own clock.

#### Built on

- **[Open protocols](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/protocol.md)**: the SDK wire protocol is specified, with a conformance suite of fourteen scenarios that needs no API keys. The [engine](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/engine.md) is documented as a library, and reads outcome checks and judges a recorded run by them.
- **[The recording format, specified](https://github.com/devjoinedthechat/shadowlap/blob/main/docs/recording-format.md)**: version 1, with packs on disk and the recordings protocol over HTTP, and Shadowlap as the reference implementation.
- **[Few runtime dependencies](https://github.com/devjoinedthechat/shadowlap/blob/main/CONTRIBUTING.md#rules-of-the-road), held by a test**. The engine, sidecar, SDKs and adapters install nothing else. Nor does the dashboard; the CLI adds commander, and the terminal UI, which the CLI uses, adds Ink and React.
- **Light to install**. Every package together is 4.1 MB to download and 16 MB installed. The `shadowlap` package exports its module and `package.json` only; its command is the `bin` the manifest names.
- **Source maps without the source**. Source maps name each file's TypeScript without carrying it, except in the SDKs, the adapters and `@shadowlap/test`, which ship their source. Their CommonJS copies are type-checked as CommonJS, and mapped too.
